# 滑块式策略调参和自动回测设计

## 目标

把当前“逐项修改参数，再点击运行回测”的流程改为直观的策略卡片和滑块调参。行情首次装载成功后，切换策略或调整参数会自动刷新回测结果，不再要求用户重复确认。

## 方案选择

考虑过三种实现：

1. 仅把数字框替换成滑块，但仍保留确认按钮。改动最小，但没有解决重复确认的问题。
2. 每次参数变化都重新下载行情并回测。交互最即时，但会产生大量网络请求，CSV 也会被重复上传。
3. 策略卡片、滑块、行情缓存和防抖自动回测。首次显式装载行情，之后只提交轻量回测请求。此方案兼顾直观、速度和稳定性，作为最终方案。

## 交互设计

- 策略下拉框替换为可键盘操作的策略卡片组。当前策略有明显选中态，并展示策略说明。
- 每个策略参数使用原生范围滑块，右侧配一个可直接输入的数值框，兼顾快速拖动和精确输入。
- 首次使用时按钮文案为“加载行情并开始回测”。行情成功装载后显示“参数调整后自动回测”，无需再次确认。
- 切换策略、拖动滑块或修改交易假设后等待 400 毫秒自动提交回测。连续操作只执行最后一次请求。
- 改变行情来源、股票代码、日期或 CSV 文件时，已装载的数据集立即失效，用户需要重新点击装载按钮。
- 正在自动回测时保留控件可操作，状态文字显示“正在自动回测…”，新操作会取消旧请求。

## 关联参数

接口策略目录中的简单双字段约束由前端即时保持合法：

- 对 `a < b`，拖动 `a` 到不小于 `b` 时，将 `b` 推到 `a + 1`；拖动 `b` 到不大于 `a` 时，将 `a` 拉到 `b - 1`。
- 调整后的值始终限制在各参数的最小值和最大值内。
- 无法自动修正或不属于简单双字段关系的约束继续走现有校验并显示中文提示。

这使均线交叉中的短周期始终小于长周期，也可复用于 RSI 上下阈值等目录约束。

## 数据流与边界

前端 API 拆成两个公开操作：

1. `previewMarketData` 负责下载或上传行情并返回 `datasetId`。
2. `runBacktestForDataset` 使用现有 `datasetId` 和最新策略参数执行回测。

首次提交顺序调用两者并保存数据集标识。自动回测只调用第二个操作。组件保存行情输入指纹；任何行情输入变化都会清除数据集标识，防止把新条件错误套用到旧行情。

组件使用单一活动请求控制器。发起新请求前取消旧请求，并只允许当前请求更新结果、错误和运行状态，避免快速拖动时旧结果覆盖新结果。

## 组件边界

- `BacktestForm` 继续负责表单、数据集生命周期和请求编排。
- 新建 `StrategyControls`，只负责策略卡片、滑块和关联参数修正，通过受控值和回调与表单通信。
- `api.ts` 负责 HTTP 请求分层，不包含 UI 状态。

不新增状态管理库或滑块依赖，使用 React 和原生 `input[type="range"]`，保持包体和维护成本不变。

## 错误与可访问性

- 首次行情请求或自动回测失败时保留当前输入，并显示现有中文错误消息。
- 自动回测失败不会丢弃上一次成功结果，用户继续调整即可重试。
- 策略卡片使用按钮和 `aria-pressed`；滑块和数值框都有独立可读标签，支持方向键、触摸和鼠标。
- 动态状态使用 `aria-live="polite"`，不打断用户连续操作。

## 测试与验收

- 策略以按钮呈现，切换后只显示对应参数滑块。
- 均线短周期和长周期发生冲突时能自动保持合法间距。
- 首次运行依次装载行情并回测。
- 行情装载后，参数变化经过 400 毫秒只调用回测接口，不再调用行情预览接口。
- 连续变化会取消或忽略旧请求，最终结果对应最后一组参数。
- 修改行情条件后停止自动回测并恢复“加载行情并开始回测”按钮。
- 前端测试、后端测试和生产构建全部通过。
