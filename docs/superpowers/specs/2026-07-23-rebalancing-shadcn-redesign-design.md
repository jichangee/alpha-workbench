# 组合再平衡与 shadcn/ui 界面重写设计

## 目标

在现有美股回测系统中完成两项相互配合的改造：

1. 在“持仓对比”工作区为每组组合增加独立的定期再平衡策略，使用户可以直接比较同一资产配置在不再平衡、每月、每季度和每年再平衡下的历史表现。
2. 使用 shadcn/ui 和 Tailwind CSS 重写整个前端界面，统一视觉语言、交互状态、响应式布局和可访问性，同时保留现有业务流程、ECharts 图表以及前后端职责边界。

本次不把再平衡加入单标的“策略回测”工作区。单标的策略仍负责产生空仓或全仓做多信号；多资产权重恢复属于“持仓对比”的业务边界。

## 方案选择

考虑过三个方向：

1. 所有组合共用一个再平衡周期，并只局部替换 UI。改动较小，但无法比较同一组合的不同再平衡方式，且界面会长期新旧混用。
2. 每组组合独立选择再平衡周期，并完整重写前端设计系统。该方案能直接支持策略比较，也能一次性建立稳定的 UI 基础，作为最终方案。
3. 建立包含整数股、现金、佣金、滑点和偏离阈值的完整组合撮合引擎。该方案更接近实盘，但会显著扩大产品口径和实现范围，不适合本次改造。

最终采用第二种方案。

## 再平衡数据模型

`PortfolioDefinition` 增加 `rebalanceFrequency` 字段，取值为：

- `none`：首日配置后不再平衡。
- `monthly`：每月最后一个共同交易日收盘后再平衡。
- `quarterly`：每季度最后一个共同交易日收盘后再平衡。
- `yearly`：每年最后一个共同交易日收盘后再平衡。

该字段默认值为 `none`，因此旧客户端省略字段时保持现有行为和结果。

每组组合可以选择不同频率。典型用法是复制相同持仓和权重，只改变频率，以隔离再平衡策略对历史表现的影响。

`PortfolioComparisonSeries` 响应增加：

- `rebalanceFrequency`：该组合实际采用的频率。
- `rebalanceDates`：实际执行再平衡的共同交易日列表。

初始配置不计入 `rebalanceDates`。最后一个数据日之后没有下一交易日可应用新权重，因此即使它恰好是周期末，也不记录没有实际作用的再平衡。

## 再平衡计算口径

行情仍使用所有请求标的的复权收盘价，并取全部标的均有有效价格的共同交易日。组合允许碎股，不单独维护现金，也不计算佣金、滑点或税费。

首个共同交易日以净值 100 和目标权重开始。此后逐日递推：

1. 使用上一交易日收盘后的实际权重和各资产当日收益率计算组合当日收益。
2. 更新组合净值。
3. 按当日收盘价计算价格变化造成的漂移权重。
4. 若当天是所选周期的最后一个共同交易日，且后面仍有交易日，则在当天收盘后把实际权重恢复为目标权重。
5. 恢复后的目标权重从下一交易日收益开始生效。

设上一日实际权重为 `w_i(t-1)`，资产日收益率为 `r_i(t)`，则：

`V(t) = V(t-1) × [1 + Σ(w_i(t-1) × r_i(t))]`

若当天不再平衡，漂移后的权重为：

`w_i(t) = w_i(t-1) × [1 + r_i(t)] / [1 + Σ(w_j(t-1) × r_j(t))]`

若当天执行再平衡，则上述净值计算完成后将 `w_i(t)` 重置为目标权重。

`none` 模式的递推结果在浮点容差内等同于当前公式：

`V(t) = 100 × Σ[target_weight_i × P_i(t) / P_i(0)]`

月、季度和年度边界只依据共同交易日序列判断。若当前日期与下一日期分别属于不同月份、季度或年份，则当前日期是对应周期的最后一个共同交易日；不假设自然月末或自然年末一定开市。

## 指标与结果

累计收益、年化收益、年化波动率、夏普比率和最大回撤继续从最终组合净值序列统一计算，公式不因再平衡模式改变。

界面在每组结果摘要中展示：

- 再平衡策略名称。
- 实际再平衡次数，即 `rebalanceDates.length`。
- 原有资产构成和目标权重。

净值图继续使用共同日期横轴，不在第一版绘制每一个再平衡标记，避免月度策略在长区间内产生过度视觉噪声。API 保留具体日期，便于测试、解释和后续扩展。

## 前端技术路线

前端保持 React 19、TypeScript、Vite、Vitest 和 ECharts，新增并配置：

- Tailwind CSS。
- shadcn/ui，使用 Radix 基础组件和 `new-york` 产品界面风格。
- Geist Sans 作为界面字体，Geist Mono 用于金额、百分比、日期和其他表格数据。
- Lucide 图标，统一使用低视觉权重的小尺寸图标。

shadcn/ui 组件源码放在 `frontend/src/components/ui`，只承载可复用界面原语。业务组件继续放在现有功能组件目录，负责表单状态、请求编排、自动回测、防抖、取消请求和结果解释。UI 原语不包含回测公式或 API 调用。

只引入实际使用的组件，不安装整个组件目录。预期使用：

- `Button`
- `Card`
- `Input`
- `Label`
- `Select`
- `Tabs`
- `Table`
- `Badge`
- `Alert`
- `Skeleton`
- `Slider`
- `RadioGroup`
- `ToggleGroup`
- `Separator`

## 视觉与布局

采用深色 zinc 仪表盘主题，emerald 为唯一主强调色。颜色、边框、圆角、背景和焦点环均来自设计令牌，不在业务组件中散落十六进制颜色。

页面顶部包含产品标题、本地运行状态和风险提示。一级工作区使用 `Tabs` 切换：

- 策略回测
- 持仓对比

桌面端使用左侧固定宽度配置面板和右侧弹性结果区。窄屏改为上下排列；数据表保留横向滚动容器，关键操作不依赖横向滚动才能触达。

### 策略回测工作区

- 使用 `Card` 分组行情来源、策略参数和交易假设。
- 使用按钮卡或 `ToggleGroup` 选择策略，保留策略说明和当前选中态。
- 使用 shadcn `Slider` 配合数值输入框调整参数，保留现有关联参数自动纠正。
- 使用 `RadioGroup` 选择卖出后持有现金或换仓。
- 使用 `Alert`、`Skeleton` 和 `Badge` 表达错误、加载、自动回测及行情是否已装载。
- 结果指标、图表和交易表使用统一 Card/Table 层级包装，但不改变结果内容和 ECharts 数据。

### 持仓对比工作区

- 每组组合使用独立 `Card`。
- 组合名称、股票代码和权重继续可编辑。
- 每张组合卡增加再平衡周期 `Select`，不同组合互不影响。
- 权重合计和校验状态使用 `Badge` 与字段说明表达，不只依赖颜色。
- 结果摘要显示策略名称和再平衡次数；净值图与指标表延续现有比较结构。

## 交互与可访问性

- 所有输入都有可关联的可见标签。
- 策略、模式和工作区选择支持键盘操作，并通过标准角色表达选中状态。
- 加载和自动回测状态通过礼貌的 live region 更新。
- 错误提示说明可采取的下一步，不显示内部堆栈。
- 正负收益不只使用颜色区分，同时保留正负号。
- 移动端交互目标保持可触达尺寸，图表和表格不挤压表单。
- UI 测试优先使用角色、标签、可见文案和用户行为，不依赖内部类名或 DOM 结构。

## API 与错误处理

现有 `POST /api/portfolio-comparisons` 路径保持不变。前端在每个组合对象中提交 `rebalanceFrequency`。

后端行为：

- 省略频率时采用 `none`。
- 非法频率由 Pydantic 返回 422。
- 权重、重复代码、日期、行情缺失和共同交易日不足等现有校验保持不变。
- 再平衡计算不引入新的外部行情请求。

前端行为：

- 新建组合默认使用 `none`。
- 新增或编辑组合时，频率作为组合定义的一部分保存。
- 请求失败保留用户输入和上一次成功结果。
- 重复提交继续取消旧请求，过期响应不能覆盖新结果。
- shadcn/ui 重写不改变策略回测的行情缓存、自动回测和取消请求机制。

## 测试设计

### 后端

- 验证旧请求省略 `rebalanceFrequency` 时默认为 `none`。
- 验证 `none` 与现有已知净值序列一致。
- 用可手算价格序列验证月度再平衡后的净值与漂移权重。
- 验证季度和年度边界识别。
- 验证再平衡在周期最后一个共同交易日收盘后执行，并从下一日生效。
- 验证最后一个数据日不产生无作用的再平衡记录。
- 验证不同组合可采用不同频率。
- 验证 API 序列化 `rebalanceFrequency` 和 `rebalanceDates`。
- 验证非法频率返回 422，现有错误映射不退化。

### 前端

- 验证每组组合默认显示“不再平衡”。
- 验证不同组合可以独立选择不同频率。
- 验证 API 请求包含每组组合的 `rebalanceFrequency`。
- 验证结果展示策略名称和再平衡次数。
- 验证 shadcn 表单具有正确标签、角色、键盘交互和错误说明。
- 验证工作区切换、自动回测、防抖、行情失效和取消旧请求等现有行为不退化。
- 验证加载、失败、空状态和成功状态在新组件结构中可见。
- 验证窄屏结构不隐藏关键操作，表格具有滚动容器。

## 实施边界

本次明确不包含：

- 偏离阈值再平衡。
- 自定义具体再平衡日期。
- 周度或每日再平衡。
- 整数股、现金余额、佣金、滑点、税费或换手率。
- 在净值图逐一标记再平衡日期。
- 改写 ECharts 或后端单标的撮合引擎。
- 修改单标的策略目录或增加第五张单标的策略卡。
- 云端部署、登录或持久化用户配置。

## 验收标准

1. 用户可以建立两至五组组合，每组独立选择不再平衡、每月、每季度或每年。
2. 相同持仓可以仅改变频率后直接比较净值和风险收益指标。
3. 旧请求和 `none` 模式保持结果兼容。
4. API 返回实际再平衡日期，结果摘要显示策略和次数。
5. 整个前端统一使用 shadcn/ui 设计语言，无明显新旧界面混用。
6. 桌面和移动布局均无关键内容溢出或不可操作。
7. 所有后端测试、前端测试、TypeScript 检查和生产构建通过。
8. 实施过程保留并兼容工作区中现有的夏普比率未提交改动。
